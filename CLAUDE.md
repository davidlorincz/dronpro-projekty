# CLAUDE.md — DRONPRO Projekty (interní řízení projektů)

Interní webová appka pro přehled firemních projektů: projekt → subúkoly, vlastníci, priority, stavy, deadliny, dashboard, portfolio, Gantt, archiv, CSV export, sdílený read-only odkaz.

## Stack (shodný s `../pujcovna`)
Next.js 16 App Router · React 19 · TypeScript · Convex 1.40 · Clerk v7 (Google login) · Tailwind 4 (CSS-first tokeny v `src/app/globals.css`) · Radix UI kit v `src/components/ui` · TanStack Table · dnd-kit · Kibo UI Gantt (vendorováno v `src/components/gantt/kibo/gantt.tsx`) · Resend.

## Struktura
- `convex/schema.ts` — users, projects, subtasks, contentItems, events, eventFiles, chatChannels, chatMembers, chatMessages, chatThreadFollows, chatMentions, chatSaved, chatTyping, presence, chatReminders, chatScheduled, chatEmoji, chatActivity, linkPreviews, activity, notifications, shareLinks, settings, notificationLog
- `convex/auth.ts` — `getCurrentUser / requireUser / requireMember / requireAdmin` (role: admin | member | restricted | viewer)
- `convex/invites.ts` — pozvánky (token, expirace 14 dní, revoke/resend); uplatnění v `users.ensureCurrentUser`
- `convex/access.ts` — viditelnost projektů: `projectScope / canSeeProject / filterVisible` + guardy `requireEditor / requireProjectAccess / requireSubtaskAccess / requireContentAccess`
- `convex/lib.ts` — sdílené výpočty: progress, deadline flag, řazení (TOP→Low, pak nejbližší deadline)
- `convex/projects.ts`, `subtasks.ts`, `content.ts`, `dashboard.ts`, `gantt.ts`, `share.ts`, `activity.ts`, `notifications.ts`, `email.ts` ("use node"), `crons.ts`, `seed.ts`, `maintenance.ts` (interní CLI údržba)
- `convex/events.ts` + `eventFiles.ts` + `http.ts` — modul Eventy a zakázky (viz níže)
- `convex/ics.ts` + `calendar.ts` + `calendarEmail.ts` — pozvánky do kalendáře (.ics)
- `convex/chat.ts` + `chatMessages.ts` + `chatAccess.ts` — chat (kanály, DM, vlákna, reakce); `chatExtras.ts` (hledání, piny, uložené, soubory, náhledy odkazů) + `presence.ts` (online, píše…) + `chatSchedule.ts` (připomínky, naplánované) + `chatPolls.ts` + `chatEmoji.ts` + `chatDigest.ts` + `giphy.ts` (GIFy) + `chatLinks.ts` (kanál projektu/akce) + `chatActivity.ts` + `links.ts` (náhledy odkazů)
- `src/app/(app)/*` — přihlášená část (layout = `AppShell` s `AuthGuard`; hlavní menu jde schovat tlačítkem nebo ⌘\ — stav v `useSidebarCollapsed`, na mobilu vysouvací panel), `src/app/login`, `src/app/share/[token]` (veřejné)
- `src/lib/upload.ts` — zmenšení fotek + upload s průběhem (eventy i chat); `src/lib/compose.ts` — Enter odešle / Shift+Enter
- `src/lib/constants.ts` — labely, barvy stavů/priorit; `src/lib/dates.ts` — ISO datumy `YYYY-MM-DD`

## Pravidla
- **cursor-pointer** na všech klikatelných prvcích (`<button>` je řešen globálně).
- **Nikdy `confirm()`/`alert()`/`prompt()`** → `<ConfirmDialog>` + `toast()` z `src/lib/toast.ts`; chyby z Convexu přes `errorToast()`.
- Brand: vždy „DRONPRO“ velkými; česká diakritika v textech, žádné unicode escapy.
- Nadpisy `h1–h6` mají globálně brand font Rapid Variable + uppercase; pro běžné titulky sekcí použij `<div className="font-semibold">`.
- Convex: `undefined` v argumentech se zahazuje → mutace `projects.update` / `subtasks.update` používají `null` = „vymazat pole“.
- Datumy držíme jako string `YYYY-MM-DD` (bez timezone). Server-side „dnes“ = `todayISO()` v `convex/lib.ts`.
- Progress = hotové / (všechny − cancelled); bez subúkolů = `null` („Bez subúkolů“). Hotové subúkoly projekt **neuzavírají** — jen banner „označit Finished“.
- Blocked vždy vyžaduje `blockedReason` (validace na serveru).
- **Eventy a zakázky**: jedna tabulka `events` s polem `kind: "event" | "job"`, dvě routy `/eventy` a `/zakazky` nad sdílenými komponentami v `src/components/events` (prop `kind` ohýbá popisky přes `EVENT_KIND_*` / `EVENT_MAIN_COST_LABEL` v `constants.ts` — u eventu „Cena stánku“, u zakázky „Fixní náklad“). Vlastní sada stavů `eventStatusValidator` (not_started → in_progress → ready_to_go → done | cancelled), **nesdílí se** se `statusValidator` projektů. Termín je `dateFrom` + volitelně `dateTo` (vícedenní akce). Materiál, vybavení a check list jsou tři pole `packItemValidator` — položka je zároveň odškrtávátko, souhrn počítá `enrichEvent`. Společný kalendář `/kalendar` (`events.calendar`) kreslí obě sekce; vícedenní akce se vkládá do každého dne rozsahu. Typ jde přepnout (`kind` v patchi `events.update`, přepínač v `EventFormDialog`) — detail na špatné routě přesměruje do správné sekce; `kind` je v `CALENDAR_FIELDS` i `fingerprint`, protože mění SUMMARY pozvánky. Úkoly eventu (`todos`) mají vlastní `eventTodoValidator` s `assigneeIds` (sdílený `todoValidator` subúkolů je bez přiřazení); nově přiřazeným jde notifikace `event_assigned`.
- Eventy **nemají vazbu na projekt** a práva jsou plochá: čte každý přihlášený (`requireUser`), edituje kdokoli kromě `viewer` (`requireEditor`), `hardDelete` jen admin a jen archivované. Do `projectScope` proto nepatří.
- Editory dílčích sekcí eventu posílají **jen změněné pole**, ne celý blok — `CostEditor` posílá `CostPatch`. Kdyby posílal celou trojici (cena stánku / náklady / výnos), přidání nákladu by přepsalo cenu stánku zastaralou hodnotou z closure a smazalo ji.
- **Kalendářové pozvánky**: `convex/ics.ts` (čistý generátor RFC 5545, bez Node), `convex/calendar.ts` (mutace + plán) a `convex/calendarEmail.ts` (`"use node"` odeslání). Rozdělení je vynucené — soubor s `"use node"` smí obsahovat **jen akce**. Odesílá se automaticky při změně `CALENDAR_FIELDS`, s debounce 3 min přes `ctx.scheduler` (`calendarJobId` se při další úpravě ruší); storna (archivace, `cancelled`, vypnutí, smazání termínu) jdou okamžitě. `UID` je stabilní + `SEQUENCE` roste → aktualizace přepíše původní událost místo duplicity; bez inkrementu Gmail změnu ignoruje. `DTEND` celodenní akce je **exkluzivní** (poslední den + 1), folding se počítá v **oktetech**, ne znacích. `ORGANIZER` je `CALENDAR_ORGANIZER` (`marketing@dronpro.cz`) a **musí to být adresa, která poštu přijme**: Gmail na ni posílá odpovědi na RSVP a bounce Googlu stačí k tomu, aby událost z kalendáře zase smazal — tohle už jednou nastalo, když organizátorem byla no-reply adresa na `updates.dronpro.cz` (doména je v Resendu `Receiving: disabled` a nemá MX). Odesílá se dál z `EMAIL_FROM`, takže se odesílatel a organizátor liší — a **musí se lišit bez `SENT-BY`**: podle RFC 5546 chodí odpověď právě na `SENT-BY`, takže jeho přidání bounce jen vrátilo (vyzkoušeno). RSVP odpovědi padají do schránky organizátora, ale appka je nesbírá — účast se drží polem Tým. Content type přílohy musí nést `method=` shodné s `METHOD` uvnitř ICS, jinak Gmail pozvánku nevykreslí. Pozvánky jdou pod kill-switchem `settings.emailNotifications` (bez `transactional`), protože jsou automatické. `calendarSync: undefined` u akcí založených před nasazením = vypnuto, aby první úprava staré zakázky nevystřelila pozvánky celému týmu. Server-only pole (`calendarUid/Sequence/SentAt/SentTo/Fingerprint/JobId`) do patch validatoru `events.update` nepatří — mění je jen `calendar.ts`; uživatelské přepínače `calendarSync` / `calendarIncludeContacts` se mění přes `calendar.setSync`.
- **Komentáře (chat)**: tabulka `comments` (`entityType` project | subtask | event + `entityId` string, u projektu/subúkolu i `projectId` → počty jedním dotazem v `projects.get`), logika v `convex/comments.ts`, UI `src/components/shared/CommentThread.tsx`. Čte každý, kdo vidí nadřazenou entitu (i viewer), píše editor přes `requireSubtaskAccess` / `requireProjectAccess` / `requireEditor`. Vzkaz ke změně priority (`subtasks.update` arg `note`) se ukládá i jako komentář. hardDelete projektu / subúkolu / eventu komentáře maže. Do `share.publicPortfolio` nepatří.
- **Chat** (`/chat`, jako Slack): tabulky s prefixem `chat` (`channel` už je kanál content plánu) — `chatChannels` (`kind: channel | dm`, DM = privátní kanál bez názvu s `dmKey` ze seřazených userIds → stejná skupina má jedno DM), `chatMembers` (členství + osobní stav), `chatMessages`, `chatThreadFollows`, `chatMentions`. Logika v `convex/chat.ts` (kanály, členství), `convex/chatMessages.ts` (zprávy, vlákna, reakce, přílohy), pravidla v `convex/chatAccess.ts`; UI v `src/components/chat`. **Přístup je plochý a nezávislý na projektech**: veřejný kanál čte každý aktivní kromě `restricted` (i bez členství = náhled), privátní kanál a DM jen členové; admin vidí metadata privátních kanálů (název, členy, archivace), obsah až po připojení (systémová zpráva to ukáže všem), DM nevidí vůbec. Píše člen nearchivovaného kanálu včetně `viewer`. `#obecne` (`isDefault`) má automatické členství přes `joinDefaultChannel` (volá `ensureCurrentUser`, `updateRole`, `setStatus`), nejde opustit, přejmenovat ani archivovat. **Nepřečtené jsou denormalizované**: tučně = `chatChannels.lastMessageAt > chatMembers.lastReadAt`, badge = `chatMembers.mentionCount` (u DM každá zpráva) — nikdy nepočítej zprávy za běhu. Systémové zprávy `lastMessageAt` nezvyšují. `inChannel` na zprávě = root nebo odpověď „poslat i do kanálu“; timeline jde přes index `by_channel_feed` a `.paginate()`. Text drží tokeny `<@userId>` / `<#channelId>` / `<!kanal>` (převod v `src/components/chat/tokens.ts`), formátování renderuje vlastní parser `MessageText.tsx` bez HTML. Root s odpověďmi se maže **soft** (`deletedAt`), jinak natvrdo i s bloby; po smazání poslední odpovědi zmizí i soft-smazaný root. Notifikace chatu (`chat_mention`, `chat_dm`, `chat_thread_reply`, `chat_channel_message`, `chat_added`) respektují `chatMembers.notify` / `muted`; odpověď ve vlákně notifikuje sledujícího jen při přechodu na nepřečtené. Přílohy stejným vzorem jako eventy (`generateUploadUrl` → POST → `send` s `storageId`, MIME a velikost z `_storage`), stahování přes HTTP routu `/chatFile?m=&s=`. Emoji picker `frimousse` stahuje data z jsDelivr CDN.
- **Chat F2** (`convex/chatExtras.ts`, `convex/presence.ts`): fulltext přes `chatMessages.searchIndex("search_text")` — výsledky se **vždy** filtrují přes `canReadChannel` (index o přístupu nic neví); filtry `v:#kanal` / `od:@jmeno` parsuje klient v `SearchView`. Skok na zprávu (`?zprava=`) dočítá starší stránky, dokud ji nenajde (max 20 stránek); odpověď ve vlákně se otevírá přes `?vlakno=`. Piny = `pinnedAt/pinnedBy` na zprávě (index `by_channel_pinned`), uložené = osobní tabulka `chatSaved`. Náhled odkazu na `/projekty|eventy|zakazky/<id>` (`LinkPreviews` → `chatExtras.linkPreviews`) projde `canSeeProject`, aby `restricted` neviděl název cizího projektu; „Sdílet do chatu“ z detailu projektu/eventu posílá obyčejnou zprávu s odkazem. „Píše…“ (`chatTyping`, TTL 6 s, cron úklid) i online tečky (`presence`, heartbeat z `PresenceHeartbeat` v AppShellu každou minutu) vyhodnocuje **klient proti vlastním hodinám** — reaktivní query se s časem nepřepočítá. Presence je **samostatná tabulka, ne pole na `users`**: heartbeat by jinak každou minutu invalidoval všechny dotazy čtoucí uživatele.
- **Chat F3**: `deliverMessage()` v `convex/chatMessages.ts` je jediné místo, které vkládá zprávu, počítá nepřečtené a posílá notifikace — volá ho `send`, `chatPolls.create` i naplánované odeslání; práva ověřuje volající. Připomínky (`chatReminders`) a naplánované zprávy (`chatScheduled`) stojí na `ctx.scheduler.runAt`: řádek se vloží **bez** `jobId`, pak se naplánuje job s id řádku a `jobId` se doplní (kvůli zrušení / změně času). Naplánovaná zpráva se odesílá s právy autora v okamžiku odeslání — když mezitím odešel z kanálu nebo je archivovaný, dostane `chat_reminder` „neodeslala se“ a přílohy se smažou. Připomínka zkontroluje `canReadChannel` až při doručení. Anketa = zpráva s polem `poll` (`text` = otázka kvůli fulltextu), nejde upravit, jen uzavřít. Vlastní emoji (`chatEmoji`, `:nazev:`) přidává admin/member, obrázek ≤ 512 kB (klient zmenší na 128 px, GIF nechá); ve zprávách i reakcích se nahrazují na klientu, smazané zůstane textem. Denní souhrn `chatDigest.daily` (cron všední dny 14:00 UTC) jde přes `notify()` typ `chat_digest` (default jen e-mail) s `dedupKey` na den. Pozor: dev deployment má `RESEND_API_KEY`, takže ruční `npx convex run chatDigest:daily` pošle skutečné e-maily.
- **GIFy (Giphy)**: `convex/giphy.ts` — akce `search` volá Giphy API s klíčem z Convex env `GIPHY_API_KEY` (klíč **nikdy do klienta**), rating `pg-13`. Do zprávy se ukládá jen pole `gif` s odkazy (`chatGifValidator`), obrázek zůstává na CDN Giphy — nezabírá naše úložiště. `deliverMessage` i `chatSchedule.schedule` odkaz validují přes `isGiphyUrl` (jen `*.giphy.com`), aby šlo vložit cizí URL. UI: `GifPicker.tsx` v composeru, ve zprávě náhled s popiskem „GIF z GIPHY“ a otevřením v lightboxu.
- **Chat F4**: `deliverMessage` zprávu vloží a čítače, notifikace i stav vláken předá `fanOutMessage` — nad 25 členů kanálu jde fan-out **na pozadí** (`internal.chatMessages.fanOut`), aby velký kanál nebo `@kanal` nepřetekl mutaci. Mazání kanálu (`chat.hardDelete`) jen označí `deletingAt` a `internal.chat.purgeChannel` maže po dávkách 200 zpráv (kanály s `deletingAt` zmizí z `mySidebar`/`browse`/`get`); `memberCount` se drží na kanálu, aby `browse` nečetl členy všech kanálů. Fulltext běží nad odvozeným polem `searchText` (bez diakritiky, `foldText` v `convex/lib.ts`) a stránkuje `paginate()` **až do naplnění 50 přístupných výsledků** — ořezat před kontrolou přístupu by výsledky ztratilo; bez textu, ale s filtrem, vypisuje poslední zprávy. Přílohy má index `by_channel_files` přes `hasAttachments`. Po nasazení je nutné jednou spustit `npx convex run maintenance:backfillChat '{}'` (dopočte `searchText`, `hasAttachments`, `memberCount`). Přeposlání ukládá **snímek** originálu (`forwardedFrom`), ne kopie příloh. Stav, Nerušit a tiché hodiny jsou v `presence` (`presence.setStatus/setDnd/setQuietHours`); `notify()` u typů `chat_*` v tomhle režimu **vynechá e-mail**, in-app notifikace zůstává, a `ChatNotifier` neukáže upozornění prohlížeče (`isQuietNow` je ve `convex/lib.ts` i `src/components/chat/quiet.ts`). Kanál projektu / akce: `chatChannels.projectId` / `eventId` + `convex/chatLinks.ts`; `postEntityUpdate()` vkládá systémovou zprávu s `bump` (kanál ztuční, notifikace nechodí) z `projects.setStatus`, `subtasks.update` (finished/blocked) a `events.setStatus`. Kanál nikdy nevzniká sám.
- **Chat F5**: **Aktivita** (`convex/chatActivity.ts`, tabulka `chatActivity`) je cílený zápis jednomu člověku — `logActivity()` volá `fanOutMessage` (mention/dm/reply), `chatMessages.toggleReaction` (jen při přidání reakce) a `chat.addMembers`; vlastní akce se nezapisují, kaskády mažou aktivitu se zprávou, kanálem i uživatelem, cron `chat-activity-cleanup` maže starší 60 dní. **Slash příkazy** (`src/components/chat/commands.ts`) se vyhodnocují až při odeslání v `Composer.runCommand()` — příkaz musí být na začátku zprávy, neznámý příkaz zprávu neodešle; nové serverové funkce si nezavádí, volá existující mutace. **Vlastní sekce** panelu jsou v `chatMembers.section` (per uživatel, `chat.setPrefs`), `orderSidebar()` z nich staví skupiny. **Náhledy externích odkazů**: `convex/links.ts` — akce `ensure` stáhne Open Graph a uloží do sdílené `linkPreviews` (TTL 7 dní, `failed` brání opakovanému stahování), query `preview` čte cache. **Pozor na SSRF**: `isPublicHttpUrl()` odmítá lokální a privátní adresy a kontroluje se i cílová URL **po přesměrování**. Klient vezme jen první externí odkaz (mimo vlastní doménu a Giphy). Ikona kanálu = `chatChannels.icon` (unicode emoji nebo vlastní `:nazev:`, validuje `cleanIcon` v `chat.ts`), vykresluje ji všude `ChannelIcon` (bez ikony `#` / zámek, u privátního kanálu s emoji malý zámek v rohu), mění ji `chat.create` / `chat.update` (`icon: null` = odebrat). **Indikátory nepřečteného** (`UnreadMark`): červené číslo = týká se mě (`mentionCount`, u Aktivity `mention|dm|reply`), tečka = jen nové zprávy (neztlumený `unread`, sledované vlákno, reakce); číslo má přednost. `chat.unreadBadge` vrací `{ mentions, unread }` → `ChatUnreadMark` v hlavním menu i na tlačítku menu v hlavičce, titulek/favicon jen `mentions`. Sbalená sekce panelu dál ukazuje nepřečtené konverzace. Přístupnost: ikonová tlačítka chatu mají `aria-label`, timeline `role="log"` + `aria-live`, sekce panelu `aria-expanded`, aktivní kanál `aria-current`.
- Soubory: Convex file storage, `convex/eventFiles.ts` (`generateUploadUrl` → klient POST → `attach`). Velikost a MIME se čtou z `ctx.db.system.get("_storage", id)`, **nikdy z klienta**; nevyhovující blob se hned maže. Limit 20 MB je dán stropem odpovědi HTTP action `/eventFile` v `convex/http.ts`, která soubory servíruje s původním českým názvem (`download` atribut přes cizí origin nefunguje). Fotky se na klientu zmenšují na 2000 px webp kvůli 1GB kvótě. `ctx.storage.getUrl()` vrací **veřejnou trvalou URL** — neuhodnutelnou, ale bez auth; do veřejného `share.publicPortfolio` se nesmí dostat.
- Notifikace: vždy přes `notify()` v `convex/notifications.ts` — respektuje `users.notificationPrefs` (in-app / e-mail per typ, defaulty v `convex/notificationTypes.ts` = kopie `src/lib/notificationTypes.ts`, **měň obě**). Typy: assigned, blocked, due_soon, overdue, finish_suggest, subtask_done, priority_changed, comment, event_assigned, event_soon, chat_mention, chat_dm, chat_thread_reply, chat_channel_message, chat_added, chat_reminder, chat_digest, deadline_changed (admin), new_user (admin), invite_accepted (admin). Globální kill-switch e-mailů: settings.emailNotifications.
- Role `restricted` („Přiřazené projekty“) nevidí **žádný** projekt, dokud nezíská vazbu (owner / spolupracující / assignee subúkolu nebo contentu s `projectId`); pak vidí celý projekt a smí v něm editovat jako member, ale nezakládá nové projekty. Každá query nad projekty musí projít `filterVisible` a každá mutace nad konkrétním projektem `requireProjectAccess` / `requireSubtaskAccess` — proto `requireMember` v `projects.ts`/`subtasks.ts` **nepoužívej** (zůstává jen u `projects.create`).
- Pozvánky: admin v /uzivatele zadá e-mail + roli + oddělení + projekty → token + e-mail přes Resend → `/pozvanka/<token>` (veřejná routa v `src/proxy.ts`). **Token v odkazu nedává přístup** — je to jen ukazatel na landing stránku; přístup uděluje výhradně shoda Googlem ověřeného e-mailu v `ensureCurrentUser`. Priorita při přihlášení: `INITIAL_ADMIN_EMAILS` > pozvánka > default `viewer/pending`. Pozvánka jen povyšuje, nikdy nesnižuje (adminovi roli nesebere, aktivnímu uživateli ji nepřepíše); projekty se přidávají do `collaboratorIds` aditivně.
- `internal.email.send` umí `attachments` (base64 + `contentType`), `replyTo` a `secondaryLink` (absolutní URL druhého tlačítka — `link` se prefixuje `APP_URL`). Má `transactional: true` pro pozvánky — obchází kill-switch `settings.emailNotifications`, který je určen pro notifikace, ne pro transakční e-maily. `cta` mění popisek tlačítka.
- Nový uživatel = `status: "pending"` bez práv (hláška „požádej admina“), admin přidělí roli v /uzivatele. Bootstrap adminy určuje `INITIAL_ADMIN_EMAILS`.
- Přihlášení jen přes Google (Clerk: e-mail kód i heslo vypnuty přes `clerk config patch`); u prod instance zopakovat.
- Položky bez termínu se v Ganttu nevykreslují s umělým datem → sekce „Bez termínu“.
- Kibo Gantt je vendorovaný kód — úpravy dělej přímo v `kibo/gantt.tsx` (má eslint-disable pro React Compiler pravidla).
